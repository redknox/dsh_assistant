# v0.5.0 Governed Personal Harness baseline

Status: **stabilization candidate**. This document describes the current repository and is the authoritative product baseline for `dsh-assistant@0.5.0`. It is not a production security certification, public release, or annotated Git tag.

## Product claim

v0.5.0 establishes TARS-NG as a usable, local, governed personal Harness:

> A user can work through durable Sessions, ask the Harness to use or construct a Capability, inspect its plan and effects, approve an exact change, activate or unplug it, and recover the local system without allowing generated code to authorize itself.

The Harness decides the next useful step. Workflow is an optional implementation form for a stable sequence, not the product controller. Tool, Skill, Connector, Extension, Workflow, and Slash Command are implementation or entry-point forms behind user-visible Capabilities.

## Preserved authority invariants

- Generated code may propose, author and validate; it cannot approve, activate, recover, push or merge itself.
- Validation is not Independent Review. Review is not approval. Approval is not activation.
- Approval is bound to the exact digest, diff, permissions and effects and resumes at most the approved action.
- Candidate execution receives typed, call-bound authority rather than ambient filesystem, process, network or secret access.
- The browser renders host-owned state; it is not a lifecycle or recovery authority.
- Capability delivery uses a dedicated Session and one native Goal, but chat history is not the source of lifecycle truth.
- Unplug and rollback retain provenance, audit evidence and dependency impact rather than silently deleting history.

## Known gaps at this baseline

1. Runtime ownership can still become confusing when an old process owns the Web UI port while lease/status metadata is stale. This is a stabilization priority.
2. Google OAuth refresh is not implemented. Feishu renewal is diagnosed and linked to reauthentication, but remains operator-driven.
3. Calendar and Obsidian generated Self-Extension vertical tests now pass through exact, host-owned isolated-runtime Broker operations; live OAuth longevity remains outside this deterministic evidence.
4. Native Workflow runs are foreground and non-resumable; long Session performance needs a reproducible soak fixture.
5. External executors remain Candidate-only and cannot safely modify the TARS-NG host. Codex has completed the bounded live acceptance. Claude Code's custom model route is detected independently from Anthropic login, but still awaits an explicitly authorized live Candidate acceptance against its configured endpoint.
6. Daily backups perform an isolated restore drill, but there is no one-click production-wide restore or product-version migration assistant.
7. No production security certification, signed installer, automatic product update, public/LAN UI, mobile distribution, marketplace, or remote Skill/plugin install is claimed.

## Stabilization exit criteria

This baseline may be called **accepted** only after all of the following are recorded against one exact commit and packed artifact:

1. Typecheck, complete test suite with no quarantined Calendar or Obsidian vertical slice, build, pack/install smoke and historical `verify:v0.2` pass.
2. Start/status/stop/restart prove one authoritative Home owner without an orphan listener or stale UI asset.
3. One real daily-use Session proves text, image input, compaction, spill, checkpoint and restart continuity.
4. Memory, Knowledge and enabled connectors expose truthful configured/authenticated/data/last-verified states.
5. Native development completes one governed Candidate; Codex and Claude each complete a bounded live Candidate run. Even after acceptance, external executors remain Experimental until soak evidence covers long runs, cancellation and restart recovery in real use.
6. Calendar and Obsidian production paths either pass isolated-runtime E2E tests or remain explicitly degraded and unclaimed.
7. A daily backup is restored into an isolated Home and its Session, Memory, configuration and committed governance state are verified.

Do not create or push `v0.5.0` from a feature branch. Tagging and publishing remain separate human release decisions.
