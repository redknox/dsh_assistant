# v0.2.x stabilization and recovery

Status: **Verified** by `npm run verify:v0.2` (`test/v0.2-regression.test.ts`). Passing that suite is regression evidence for the local `0.2.0` baseline, not a production security certification.

This document does not change the v0.2.0 architectural model. It records how to re-verify, recover, and back up the released governed Self-Extension baseline.

## What v0.2.0 guarantees

```text
Self-extension without self-authorization
Validation != Approval
Approval != Activation
Exact candidate/diff/fingerprint binding
Active versions are immutable; changes create a new candidate
Transactional, reversible activation
Recovery authority outside generated/model-facing code
Safe Mode excludes generated/optional extensions
Durable authority, not directory presence, authorizes remount
Restart never silently expands capability, permissions, or authority
```

Historical v0.1.0 remains the Assistant Core MVP. DSH dependencies stay at `0.1.0-rc.8`. There is no schema migration layer in v0.2.x: unknown future `authority.json` / backup schemas fail closed.

## Release-confidence command

After ordinary `npm test`:

```sh
npm run verify:v0.2
```

It runs the product-level suite only: clean boot, governed lifecycle, rollback, missing/mutated artifact, interrupted activation/rollback, persisted Safe Mode, corrupt/unknown/inconsistent durable state, backup/restore, and retired-artifact powerlessness. It does not call live providers or use external credentials.

## Operator diagnostics

`npm run self-extension -- status` prints a secret-safe surface:

```text
mode / registry-generation / activation
active owners
current-digest / current-fingerprint
lkg-generation / lkg owners
last-failure / persistence / reasons
restart-recovery-required
```

Typical `reasons` values: `missing-active-artifact`, `digest-mismatch`, `inconsistent-active-owner`, unsupported schema. Do not read raw `authority.json` unless diagnosing a persistence parser failure.

## Recovery drills

Use a fresh process for each step (`bootAssistantControl({ home })` or restart the CLI). Do not reuse in-memory objects from the previous runtime.

| Drill | Expected |
| --- | --- |
| Remove a committed generated artifact, reboot | Safe Mode, no generated mount, `missing-active-artifact` |
| Mutate a sealed committed artifact, reboot | Safe Mode, `digest-mismatch` |
| Crash before the durable activation commit, reboot | Prior LKG remains authoritative |
| Interrupt rollback, reboot | Rollback completes or Safe Mode with recovery-required |
| Enter Safe Mode, reboot | Generated extensions stay excluded; recovery control remains |

Trusted follow-up: `self-extension disable <owner> <version>`, `rollback`, or `safe-mode exit` (exit does not remount a failed generated plugin).

## Backup and restore

Authoritative snapshot contents:

```text
authority.json          Registry + Governance + Activation + Recovery/LKG
candidates/index.json   Artifact index / retention
candidates/<id>/        Required sealed artifacts
manifest.json           Backup kind/schema only
```

Not included: secrets, credentials, `$DSH_HOME`, session store, personal memory, environment variables.

```sh
export DSH_ASSISTANT_HOME=/path/to/home
npm run self-extension -- backup /path/to/backup
npm run self-extension -- restore /path/to/backup
# then start a new process
npm run self-extension -- status
```

Restore replaces `{home}/self-extension` after validating the backup manifest and current authority schema. The next boot still runs digest/preflight remount. Restore never auto-activates an approved-but-inactive candidate.

`backup` / `restore` require a `RecoveryRoot` credential (`source: operator-cli`). They are not on `ctx.extensionRecovery`.

## What requires Safe Mode

- Missing or mutated committed generated artifacts
- Registry `active` generated owners that are not in the committed activation snapshot
- Unknown or corrupt `authority.json` / candidate index / backup schema
- Persisted `safeMode: true`

## Intentionally not covered

- A second generated product capability
- Plugin upgrade lifecycle or generated → managed promotion
- Enterprise / remote / HA backup
- Live vendor providers
- Automatic schema migration
- Production security certification
- `v0.3.0` work, package bumps, or git tags
